# 每日贴士(daily 档编排规则)

> 主动层:把档案里「今天该被推出去」的信号编排成每日贴士卡。触发词
> 「今日贴士」「tip」,或用户环境每日 Cron。**不是新知识源**——全部内容
> 从 档案×知识库×日历 路由而来,不产生新断言;活动/观察点组合标【推断】。
> 流程:Run `scripts/daily-tips.sh data`(候选信号+近 7 天去重记录)→ 按本文
> 编排 → 输出今日贴士卡(templates.md)→ Run `scripts/daily-tips.sh record
> data cat:key[:main] ...` 落当日记录(同日重跑覆盖;写入证据=脚本输出)。
> **Cron 场景追加**:把贴士卡写入 /tmp/pg-tip-<date>.md 后 Run
> `python3 scripts/feishu-tip.py /tmp/pg-tip-<date>.md` 推飞书卡(webhook=
> ~/.config/feishu/webhook_url;失败不阻塞,提示即可——对话场景用户就在,
> 不推)。

## 瀑布优先级(主推从上往下选,先到先得)

1. **closedloop 闭环**:今日到期回访 > 过期近(≤3 天)> 过期久(轻提一句)。
   到期回访是主推首选——闭环纪律的推送版。pendingCare 开题进入所述窗口
   尾段(如「1-2 周内」的第 10+ 天)与到期回访同优先级。家长在对话中确认
   已处理 → 提示 `set-followup-status` 收口,不再重复推。
2. **action 策略今日动作**:在管问题 brief.how 轮换单条,不整段复述。
   轮换规则:看脚本输出的近 7 天记录,**没出过的优先**(key=`P1-how3` 式),
   全出过则出间隔最久的。绑定同一问题的策略与问题共用 how(如 S4↔P1),
   不重复推;无 issue how 绑定的策略读 child.json 策略区提炼一条。头 7 天
   可每天出,之后降到隔天。**执行困难日最小剂量**(孩子生病/家长累/外出日,
   不弃练只降量):每条 how 配「最小版」口径并在贴士注明「今天保底做这一件
   就够」——如便秘四件事最小版=西梅一份照旧、共读最小版=3 分钟读一本旧的;
   与「退步不算失败」同源(fears.md §2 渐进纪律)。
3. **anticipatory 前瞻窗口**:读 knowledge/anticipatory.md,按脚本输出的
   日期+月龄匹配窗口。时效类(流感最佳窗口/报名类)在窗口内必出,可占
   轻附位;认领的 reminders 仅「临近」档(≤14 天)值得占位,脚本已标
   「远·过滤」的不出。通用规则沿用:通用口径提示查证本地信息。
4. **milestone 发育观察点**:月更一条,当月已出过(记录 key 同月龄前缀,
   如 `m32-*`)不换新。结合气质/兴趣把 CDC 能力项具体化(「搭磁力片时
   留意是否出现『先…再…』的剧本顺序」)。进入检查点窗口(距下档 ≤1 月)
   时改为提示盘点(见 anticipatory.md 发育盘点行的时机规则,不回溯)。
5. **activity 今日活动**:兴趣×季节×当前问题×照顾分工组合,按
   「当前能力+半步挑战」公式(activities.md §1);当前问题可顺带挂目标
   (便秘→户外活动量;吃饭要喂→帮厨类)。必标【推断】。
   **星期视角(按行为周期定时,不只按日历轮;事前规划优于事后补救)**:
   周五出「周末预告」(明天谁带/周末户外安排);周六日把活动指给当天
   主力照顾者并给「外婆/爸爸执行版」简化口径(按档案 caregivers 原文,
   不做星期推断——只在档案明说分工时用)。近期事件(脚本 [近期事件] 段)
   里有晨醒/夜醒/新情况的,活动或观察点优先挂上去。
6. **readaloud 共读微技巧**:PEER/CROWD 单式或「过去事件对话」轮换
   (activities.md §4 / yuwen.md §2.7),基于档案已有绘本偏好出题。
7. **weekly 本周亮点/给家长**:每周 ≤1 条。从档案提好消息(effective
   策略、里程碑全会、常模内判读),或一句家长自我关怀。对抗焦虑,
   贴士不能只是待办清单。

## 兜底

无 closedloop/action/anticipatory 时,主推从 milestone/activity/readaloud
里选。知识科普兜底**只出与 currentFocus 相关主题**的知识页条目(如
便秘→nutrition/如厕页),不出随机迷思;连相关条目都没有就只出活动/共读,
宁缺勿滥。

## 克制纪律(硬线)

- 总量 ≤3 条,主推 1 条(主推=「为什么是今天」最硬的那条)。
- 同 key 7 天内不复现(以脚本 record 记录为准)。
- **情境细节零编造(2026-10-20 判例:「今天在外婆家玩了什么」——外婆来自
  caregivers 字段,今天在哪档案并无记录)**:示例话术/活动场景不得预设
  未核实的地点/人物/今天发生的事——用占位问句(「今天玩了什么」)或
  档案 note 锚定的真实事件;组合档案字段推出的场景仍属推断,写成
  既成事实=失败。
- 家长认领的动作(约问诊/报名/立追踪)走 `update-child.py add-reminder`
  等对应子命令——**贴士本身不写 child.json**,只落 daily-tips.json。
- 每条带锚点:问题/策略 ID、知识页+T 级、【推断】(活动/观察点必标)。
- 星期仅日期语境;照顾分工按档案原文引用,不做星期推断。

## 与其他档的关系

- 家长对某条追问(「为什么」「便秘怎么办」)→ 正常走对应档(E/L2/L3/
  知识路由),贴士只是入口。
- Cron 生成(无人对话):直接输出+record;对话生成:同样输出+record,
  追问按上一条处理。
- 贴士里的断言与知识页冲突时,以知识页为准(贴士是路由不是源)。
