> 性质:现状审计 + 外部调研 + 规范提案;**未动代码**,档位与落地节奏待用户拍板。

## 一、现状审计(机械扫描 web/src,2026-10-21)

### 1.1 字体族——有规范,执行一致 ✅

`design-system.json` typography 节已定义且全站一致:

| 用途 | 栈 | 出处 |
|---|---|---|
| 正文/UI | `-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif` | style.css body;ShareModal 独立重申一份(长图导出场景,防宿主页面污染,合理) |
| 数字(第一语言) | `Georgia, "Times New Roman", serif`(hero 54 / 计数 27 / 徽章日期) | design-system.json「填表笔迹感」 |
| 站点 mono | `ui-monospace, Menlo, monospace` | site/ 生成页 |

升级空间(零成本,见 §3.1):栈首加 `system-ui`、补 `HarmonyOS Sans SC`/`MiSans`(国产安卓)与 `Hiragino Sans GB` 回退。

### 1.2 字号——无规范,散布 22 种值 ❌(核心问题)

全站 `font-size` 显式声明共 ~185 处,取值 22 种(6/9/10/10.5/11/11.5/12/12.5/13/13.5/14/14.5/15/15.5/16/16.5/17/19/20/22/24/27/54)。频次与角色:

| 值 | 频次 | 主要角色 |
|---|---|---|
| 13.5 | 22 | **事实正文主档**:卡片行式内容/时间轴/详情正文 |
| 12.5 | 22 | 次要信息行(meta/事件体/知识条目) |
| 11.5 | 17+ | 辅助小字(来源行/hint/日期徽章) |
| 12 | 30 | meta 副行/按钮/说明(与 11.5、12.5 角色高度重叠) |
| 11 | 23 | 极辅助(徽章/eyebrow 标签/来源;与 11.5 重叠) |
| 13 / 14 | 19 / 6 | 与 13.5 角色重叠 |
| 14.5 / 15 / 15.5 | 4 / 6 / 1 | ShareModal 长图正文与少量强调行 |
| 16 / 16.5 / 17 | 4 / 2 / 1 | 卡头标题(.cband h3=16)与 kbp-title(17) |
| 19 / 20 / 22 | 2 / 1 / 2 | 覆盖层/分享卡大标题、孩子名/文档 h1 |
| 10.5 / 10 / 9 / 6 | 7+ | SVG 刻度文字与状态徽章 .st |
| 24 / 27 / 54 | 各 2 | Georgia 数字(display 档,已有规范) |

两个结构性问题:
1. **±1px 内挤了 4 档**(11/11.5/12/12.5 共 92 处)——视觉不可分,纯历史累积;
2. **body 未声明基准字号**——未显式设号的元素(如 toolbar 品牌名)吃浏览器默认 16px,比全站正文主档还大,基准是「隐式的」。

### 1.3 行高——半有规范

显式声明 13 种(1~1.9);body 全局 1.6。分布:1.55(9)/1.5(5)/1.6(4)/1.9(4,时间轴紧凑行)/1.45/1.7/1.25(大标题)/1(数字 hero)。
判定:正文 1.6 与中文舒适区一致;散值(1.35/1.4/1.65/1.75)属微调噪音,可归档。

### 1.4 字重——有一个跨平台渲染坑 ⚠

分布:**600 用 32 处**、700 用 17 处、500 用 4 处、400 用 5 处。
问题:中文系统字体普遍只有真 400/700 两档——微软雅黑只有 msyh/msyhbd 两库;PingFang SC 在部分环境数值字重失效只认 bold;Android 中间值全回退、700 触发伪粗。**600 在 Mac 是真半粗、在 Windows/安卓会漂移成 400 或伪 700**,跨设备不一致。

### 1.5 letter-spacing

8 种:.04(8)/.06(4)/.08(5)/.15/.2(2)/.22em 等。design-system.json 已定「eyebrow=sub 色 .22em」——.15/.2/.22 三档并存属漂移;.04/.06/.08 标题字距三档并存同理。

### 1.6 第二界面:site/(官网知识子站)

同字体族;字号另一套(16 正文/13.5 辅助/30-24 标题)——**阅读型页面取大正文合理**,与 app(信息密集板)分属两种密度,不建议强行同阶。

### 1.7 标点体系——自成一体的「半角体系」,非国标中文标点(2026-10-21 补)

程序审计(CJK 邻接的半角标点计数):

| 层 | 中文后半角标点 | 全角逗号/冒号/括号 | 句号 | 「」 |
|---|---|---|---|---|
| 知识库 md | 8035 | **0 / 0 / 0** | 1156 | 1561 |
| UI 模板 | 25 | 0 / 3 / 0 | 3 | 2 |
| 轮播贴士 | 130 | 0 / 0 / 0 | 3 | 69 |

即现状是一套**执行极其一致的写作纪律**:逗号/冒号/分号/括号用半角,句号/破折号(——)/省略号用全角,引号用「」(非国标"",系项目语感选择,1561 处)。问题:不符合 [GB/T 15834—2011《标点符号用法》](http://www.moe.gov.cn/ewebeditor/uploadfile/2015/01/13/20150113091548267.pdf)(正式中文出版句读应全角;行末全角标点压缩半宽由排版引擎处理),面向公众的 site/ 官网与分享产物观感偏「技术文档风」。夹用英文的场景另有 [CY/T 154《中文出版物夹用英文的编辑规范》](https://www.nppa.gov.cn/xxgk/fdzdgknr/hybz/202210/P020221004608768453140.pdf)可参照(中文句子用中文标点,英文短语内部保持英文标点)。

### 1.8 字色——变量体系存在,但有两个实质问题 ⚠(2026-10-21 补)

声明分布:`color: var(--*)` 227 处(体系执行良好);**裸 hex 文字色 5 处**绕过变量:
`#5b564d`(style.css:122,退役 strategy 卡残留)/`#9c5535`(CardManager 提示暖棕)/`#8a5a2a`(KnowledgePage err 提示暖棕)/`#9aacba`(ShareModal 脚注+划线行 ×2,比 sub 更浅,白底对比约 2.4:1)。

**WCAG 对比度实测**(白底 #fff,程序计算):

| 色 | 对比度 | AA 正文(≥4.5) | AA 大字(≥3.0) |
|---|---|---|---|
| --ink #1e3a52(正文) | 11.78 | ✓ | ✓ |
| --ink-blue #2f5470(标题) | 8.01 | ✓ | ✓ |
| --err #b04a4a | 5.35 | ✓ | ✓ |
| --todo #c25a4e | 4.32 | ✗ | ✓ |
| --ok #4a8a6a | 4.09 | ✗ | ✓ |
| **--sub #7d92a3(辅助,11.5/12.5px 高频)** | **3.22** | **✗** | ✓ |
| **--watch #c98a2d** | **2.93** | **✗** | **✗** |
| --sub 于 accent-soft 底 | 2.89 | ✗ | ✗ |

问题聚焦:**辅助小字(--sub)与「观察中」徽章(--watch)不达 AA**,且 sub 恰好用在最小的 cap/sub 两档上(11.5/12.5px,远低于大字豁免线);状态徽章 10.5px 用 ok/todo 同样处于 4.5 之下。主文字色(ink/ink-blue/err)全部达标。

## 三、规范提案

### 3.1 字体族(两栈一议)

```css
/* 正文/UI:升级版(全系统字体,零加载成本) */
font-family: system-ui, -apple-system, "PingFang SC", "HarmonyOS Sans SC",
             "Hiragino Sans GB", "Microsoft YaHei", sans-serif;
/* 数字:维持 Georgia 衬线不变(设计系统已有定论) */
```
不引入 webfont(体积/加载/离线文件模式三重成本,与「双击即开」冲突)。MiSans 可选加入(小米设备),排列在 HarmonyOS Sans 后。

### 3.2 字阶(4 常用档 + 4 场景档)

**常用 4 档**(覆盖 ~92% 声明):

| token | px / 行高 | 字重 | 吸收现状值 | 角色 |
|---|---|---|---|---|
| `micro` | 10.5 / 1.4 | 400 | 9、10、10.5 | SVG 刻度、状态徽章;**新代码禁用,仅存量** |
| `cap` | 11.5 / 1.45 | 400 | 11、11.5 | 辅助小字:来源行/hint/日期/eyebrow 标签 |
| `sub` | 12.5 / 1.5 | 400 | 12、12.5、13 | 次要信息行:meta/事件体/按钮 |
| `body` | 13.5 / 1.6 | 400 | 13.5、14 | 正文主档:卡片行式内容/详情/时间轴 |

**场景 4 档**:

| token | px / 行高 | 字重 | 吸收 | 角色 |
|---|---|---|---|---|
| `body-l` | 15 / 1.65 | 400 | 14.5、15、15.5 | 分享长图正文/知识库正文(转发阅读场景,大半档) |
| `title` | 16 / 1.35 | 700 | 16、16.5、17 | 卡头标题(.cband h3)/区块标题 |
| `title-l` | 20 / 1.3 | 700 | 19、20、22 中的标题类 | 覆盖层标题/文档 h1(22 并入或保留由 §4-3 拍板) |
| `display` | 27 / 54 Georgia | 700 | 不动 | 数字第一语言(design-system.json 已有) |

### 3.3 字重——收敛为 400 / 700 两档

- 600(32 处)→ 700(接受视觉略重)或逐处降 400(标签类);**不再新写 600**;
- 500(4 处)→ 400;
- 理由:跨平台一致性 > 半粗的精细度(§1.4);不引 webfont 补真 600。
- 例外:Georgia 数字 hero 维持 700。

### 3.4 行高与字距

- 行高三档:标题 1.3 / 紧凑行 1.5 / 正文 1.6(大数字 hero=1 不变;时间轴 1.9 属行距密度微调,可保留为特例并注释);
- letter-spacing 两档:标题 .06em / eyebrow 标签 .2em(收敛 .04/.08/.15/.22 → 就近归档)。

### 3.5 基准声明

`body { font-size: 13.5px; }` 显式声明基准,消灭「隐式 16px」(toolbar 品牌名等未设号元素随之归位,视觉变化需过一眼)。

### 3.6 字色——档位 × 颜色配对(补入,2026-10-21)

**角色配对表**(颜色变量体系维持不动,配对进字阶):

| 字阶 | 标准色 | 例外 |
|---|---|---|
| title / title-l | `--ink-blue` | — |
| body / body-l | `--ink` | 行内强调 `--ink-blue` + 700 |
| sub | `--ink` 或 `--sub`(次要信息) | — |
| cap | `--sub` | 来源行/日期 |
| micro(徽章) | 状态色 `--ok/--watch/--todo` + 同色描边 | 描边式徽章,无底色块 |
| display(Georgia) | `--ink-blue` | — |

**对比度处置(待拍板,见 §4-6)**:三个方案——
(a) 维持现状:接受辅助字与 watch 徽章不达 AA(图纸的浅灰蓝气质优先,信息属次要层);
(b) 全量达标:--sub → #5f7386(4.90:1)、--watch → #a06a15(4.60:1),全站辅助字变深一档,图纸的「轻」感略损;
(c) 折中:--sub 加深到 #6b8095(4.08:1,仍差 AA 一线但明显改善)+ 仅徽章文字换深一档状态色。
推荐 (c):辅助字是次要信息层,4.0 出头在实机可读性已够,同时把「连大字豁免都不达标」的 watch 拉回线上。

**裸 hex 清理**(5 处):`#9aacba`×2 → `--sub`;`#5b564d` → 随退役卡样式删除;`#9c5535`/`#8a5a2a`(提示暖棕)→ 若保留提示语义则登记新变量 `--hint`(取 #8a5a2a,对比 5.1:1),否则归 `--watch`。清理后 `check-card-style` 补一条:文字色裸 hex 即红(现门禁只管 style 块内 hex,含 background 等,文字色实际已覆盖;cards/ 外组件靠 review)。

### 3.7 数字排版:双轨制与等宽(2026-10-21 补,用户提出对齐问题)

**中文/数字双轨现状**(设计系统有意为之):
- **字体有区别**:中文走系统 sans;数字走 Georgia 衬线(`.num-serif`/`.num-hero`/`.num-mid`/`.due-b`),「数字是第一语言,serif 数字=填表笔迹感」;
- **颜色无区别**:数字不单独配色,与所在文字层共用同一 token(仅展示性计数惯用 `--ink-blue` + 700);
- **视觉大小有暗差**:Georgia 同字号 x-height 偏小,与黑体混排时数字看起来小半档——现状未做补偿,可接受并记录;如需补偿,数字侧 +0.5px 或用 `font-size-adjust`(浏览器支持零散,不建议)。

**等宽(对齐)问题**——用户实例:「10-17」与「10-20」宽度不同,同格式列表后文错位。机制核查:
1. 全局 `body { font-variant-numeric: tabular-nums }` 已声明(style.css:11)且多处组件重申——**声明层已尽力**;
2. 但 **经典 Georgia 不带 tnum OpenType 特性**(其数字为老式比例字),tabular-nums 在 Georgia 上是空操作——`.due-b` 日期徽章、ShareModal 日期等 Georgia 场景的等宽声明实际无效;
3. 系统 sans 侧:SF Pro/PingFang 支持 tnum,Windows 雅黑支持情况不一——跨平台不保证;
4. **唯一跨平台保证等宽的方案是等宽字体栈**(`ui-monospace, SFMono-Regular, Menlo, Consolas, monospace`;site/ 的代码块已在用)。

**方案(分歧 7,待拍板)**:
- (a) 维持现状:接受日期列错位(最多 ~3px/行);
- (b) 列对齐场景换 mono:时间轴日期、表格数字列、徽章日期用 `.num-mono`(新工具类,ui-monospace 栈);display 大数字(54/24)保持 Georgia——**推荐**:对齐需求集中在列表列,mono 的机械感与图纸气质相容,影响面小;
- (c) 日期全部走 sans + tabular-nums:Mac 上生效,Windows 视雅黑支持情况,不保证。
demo 页已嵌实测脚本,在真实浏览器里现场量出各方案宽度(无头环境字体匹配不可信,以本机实测为准)。

### 3.8 其他维度清单(除颜色/字体/字号之外,2026-10-21 补)

| 维度 | 现状 | 规范态度 |
|---|---|---|
| 行高/字重/字距 | 见 §3.3/3.4 | 已入规范 |
| 等宽数字 | §3.7 | 分歧 7 待拍板 |
| **用户字号缩放** | 全站 px,不随浏览器字号设置缩放 | 本地工具可接受;记录决策「不迁移 rem」,若未来做无障碍诉求再议(WCAG 1.4.4 要求 200% 文本缩放,px 全站 + 浏览器整页缩放可达标) |

### 3.9 标点规范(2026-10-21 补,用户提出)

**规则本体**(按 GB/T 15834 + CY/T 154,结合项目语感):
- 中文句子内的逗号/冒号/分号/问叹号/括号 → 全角(，：；？！（）);
- 引号**保留「」**不转 ""(1561 处的项目语感,与国标引号二选一,保留特色);
- 句号。/破折号——/省略号……/间隔号·维持现状(已全角);
- 纯英文语境标点保持半角:(AAP, 2019)/d=0.39/10-17/58%/§3;
- 数字与英文缩写落在中文句中时,其前后仍用中文标点(夹英文规范)。

**实现路径(分歧 8,待拍板)**:
- (a) 维持现状:半角体系零改动,观感保持「技术文档风」;
- (b) **渲染层转换(推荐)**:显示面(app 知识面板 md_to_html / site 构建 / 分享卡 / 轮播贴士渲染)把「CJK 邻接的半角标点」机械转全角,代码块与 SVG 跳过;md 源与数据文件零 diff——「机械操作交给代码,语义留读侧」铁规的显示层应用;转换函数进三处渲染入口各调一次,带 fixture 测试;
- (c) 全量改源:存量 8035 处一次性脚本转换+人工复核 corner case(引号内英文、括号内引用),写作纪律同步改全角——彻底但 diff 巨大,知识库是审计资产,不建议。
