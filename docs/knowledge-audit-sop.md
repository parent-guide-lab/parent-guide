# 知识库引用审计 SOP(可复用资产)

> 沉淀自 2026-10-08~09 三轮实战(5+3 subagent,~150 断言,41 处修正全部发布)。
> 本篇回答两个问题:新增知识怎么审、想全量审怎么做;以及抽样的边界怎么补。

## 1. 触发与四种模式

| 场景 | 模式 | 预算 | 说明 |
|------|------|------|------|
| **新文件入库** | **全审**(非抽样) | ≤8 检索+6 抓取/篇 | 每条承重断言逐条过;新文件小,标准预算通常够 15-30 条。**入库第 4 道门**(见 knowledge/README 入库清单),不过不全 |
| **存量轮转** | 深审 1-2 篇/次,**逐句级** | ≤10+8/篇 | 按台账轮转,12 篇一轮≈一年全覆盖;逐句=行文里未标注的断言也要过 |
| **版本敏感重查** | watchlist 全查(§5) | 每次 1-3 检索 | 触发:周期盘点/重大改版消息(如免疫程序换版) |
| **手动全量** | 12 篇并行,标准预算+**两轮制** | 8+6/篇/轮 | 今天这套:第一轮审+第二轮(用户拍板后)续核耗尽项+取原文;分 5 个 agent 每人 2-3 篇 |

## 2. 标准审计协议(subagent prompt 模板,实战验证)

> 2026-10-19 增「冗余/可压缩」顺带观察:知识库纵向增长(单文件行数/速查行
> 膨胀)挂审计层判,不设机械硬界。边界:SKILL.md 判例区属 skill 侧、无轮转,
> 不在此覆盖内。

```
你是知识库引用审计员。仓库 /Users/zhuyuchen/ai/parent-guide。任务:按调研纪律
标准审计 knowledge/{文件}.md{(+文件2)}。

【准备】先读 skills/parent-guide/references/research.md(七步内核标准),再读
审计对象全文。

【审计对象】承重断言(数字/阈值/时限/T1T2红线/机构直接引用/研究结论),
{全审模式:逐条不漏;轮转深审模式:逐句,行文中未标注的断言也算}。逐条核对:
①来源存在吗②真的这么说吗(数字与方向)③有无更新版本取代(指南改版/机构口径
更新/页面迁移)。

【重点断言】{按文件预填,如:WS/T 579 各月龄区间/21:00 就寝/潜伏期 20min}

【方法】WebSearch+WebFetch;溯源分级:原文级=抓到来源页面正文,摘要级=仅
搜索摘要;转述回溯,回溯不到=存疑。预算:≤{N}检索+{M}抓取;优先级=
T1/T2>数字断言>机构口径>研究结论;耗尽列「未核清单」,不硬核。

【判定】✅通过/⚠️偏差(来源存在但不符,写清两边)/❓存疑(查不到)/
🕐过时(有新版,写明)/⏭未核。

【冗余/可压缩(顺带,不占检索预算)】①目标文件行数报数,参考线 ~500 行
——超线只报数不判错,判断「内容必要/该拆该删」并给理由;②§0 速查行是否仍
一行抓住主线(速查行=入口指针,膨胀成内容副本即报);③与相邻主题文件/
knowledge-index §2 该篇速查行的同义重复段。

【输出】①逐条表写入 /tmp/knowledge-audit/{slug}-audit.md(断言≤40字|引用
来源|判定|证据 URL+分级+原文短引|建议);②最终消息只回:总统计+非✅条目详情
+冗余建议(如有,含行数与理由)。

【铁律】不修改仓库任何文件;引号=来源原话;查不到=存疑不猜;区分
「来源不存在/说法不符/被更新取代」三种失败。
```

## 3. 修正执行流程(审计之后)

⚠️/🕐 汇总分级(A 过时=家长侧已错/B 偏差=引用错误/C 待核)→ **用户拍板** →
主会话修文件:①正文修正+头注加审计行(带底稿路径)②同源双侧同步
(knowledge-index §2 / site-src/quickref.md)③`audit-citations.sh 对该文件
单独跑` ④check-knowledge+fixtures ⑤site 重建 ⑥commit/publish/push ⑦台账更新。
冗余建议同呈拍板,不进 A/B/C;采纳后走上述同一流程(压缩也改正文,门禁同样
过一遍),未采纳记台账遗留栏挂账。

## 4. 铁律(三轮实战沉淀,逐条有实证)

1. **agent 只读不改**;修正由主会话经用户拍板执行;
2. **两轮制**:第一轮预算耗尽时的非原文级判断只标「待核」,不得触发修改
   (实证:第一轮判 AAPD 2024「疑被 2026-27 版取代」并据此改了引用,第二轮
   抓到官网现行 PDF 即 2024 版原文,错误修正被推翻改回);
3. **原文级才能定案数字/口径**;反爬 fallback 阶梯:换路径变体 → PDF 用
   curl 下载本地解析(WebFetch 拒 PDF 时)→ **Europe PMC REST**(PubMed
   cookie 墙的有效替代,`ebi.ac.uk/europepmc/webservices/rest/search?query=EXT_ID:{pmid}&resultType=core&format=json`)
   → 官方公告/权威转述(降级明说);
4. **fixture 绿≠文件绿**:commit 前对改动的 knowledge 文件单独跑
   audit-citations.sh(发布门的 knowledge 审计线不在 fixture 测试里——实证:
   eczema.md 被门拦下一次);
5. **新 docs 目录登记 publish EXCLUDE**(对账门会拦未分类目录——实证:审计
   底稿目录被拦一次);
6. 中途失败的 publish 会留公开仓工作区脏(staging swap 已执行未 commit),
   恢复=公开仓 `git reset --hard + git clean -fd` 后重跑。

## 6. 台账

`docs/knowledge-audit-LOG.md`:每篇最近审计日期/轮次/判定统计/遗留/下次深审
档期。轮转规则:按「上次深审最早」优先;新入库文件从「全审」起算。

## 7. 抽样的边界(诚实声明)

标准模式是「承重断言类型全覆盖、条目深度受预算约束」,不是逐句。非承重行文
中的未标注断言靠两种机制兜:①轮转深审的逐句模式(一年一轮全覆盖)②日常
dogfooding 的依据随行纪律(输出时断言无锚点=失败,会把漏网断言顶出来)。

## 8. 知识库更新场景 × 审核接线(哪些自动、哪些留人)

| 更新场景 | 触发路径 | 审核怎么走 |
|---|---|---|
| 缺口调研→官方晋升 | 家长对话(conversation §3 ③) | **协议自动**:草案必须附审计结果才进拍板(增补部分逐断言全审/新文件全审);audit-citations 由 publish 门机械把关 |
| 蒸馏生产线(材料/语料) | 维护者 | 入库四件套第 4 道(README):subagent 全审,不过不全 |
| BACKLOG 批量补库 | 维护者 | 同上 |
| 审计修正自身 | 本 SOP | 修正文件复检(audit 单跑)+发布门 |
| 新文件入库 | 任意 | 四件套(三要素/audit-citations/官方关系/全审) |
| **轮转深审** | 用户说「轮转深审」→ **skills/audit-knowledge**(repo 第二 skill)按 LOG 选片、逐句模式执行 | — |

「自动」的边界(诚实):机械层(存在性对账)在 publish.sh 里全自动;LLM 层
(语义核实要花检索预算)无法脚本化,靠**协议强制前置**(草案无审计不进拍板)
+ skill 一键调度(audit-knowledge)。可再加 Cron 定时(如每月自动发起轮转
深审),属用户侧配置,需要时建。
