# blocks-spec(页面积木规范)

> 这份文档写给**用户的大模型**看:用户的 AI 读它来修改 `data/page.json`,为家长定制成长视图。
> 设计原则:AI 只改 JSON,不生成代码;渲染器负责校验与兜底。

## 数据文件位置

- `data/child.json` — 孩子档案(单文件,含档案/追踪/回访/速记;键名任意,页面自动取第一个非 `_meta` 键)
- `data/page.json` — 页面配置(本文件讨论的对象)

## 卡片分两类(核心概念)

| | 功能卡(内置) | 自定义卡 |
|---|---|---|
| 数据来源 | 自动读 `child.json` 对应数据区 | 内容全部在 block 的 `props` 里 |
| 谁来更新 | 对话里的写入动作(update-child.py)自动更新 | 家长/AI 直接改 props 文本 |
| 空态 | 引导文案(引回对话) | 「内容为空」提示 |
| 典型用途 | 档案/里程碑/问题/生长/待回访/提醒/速记 | 奶奶须知/出门清单/辅食黑名单 |

**边界:自定义卡不引用 child.json 字段**——child.json 是脚本契约(update-child.py/hot-context.sh),页面配置不往里写数据;反过来功能卡也不需要 props 塞内容。两类卡在 page.json 的 blocks 数组里平权混排。

## page.json 结构(v2:网格坐标布局)

```json
{
  "version": 2,
  "title": "页面标题",
  "child": "child.json 里的孩子键名(可省略,默认取第一个)",
  "layout": { "cols": 12, "rowHeight": 72, "margin": 12 },
  "blocks": [ ...卡片数组,x/y 决定位置,w/h 决定宽高(网格单位)... ]
}
```

布局模型与 grid-layout-plus 同构(`{x, y, w, h}`,12 列网格)。本地服务模式下家长可拖拽/拉伸直接改这些值;AI 改这些值的效果与之完全等价。

## 卡片通用字段

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | string | 必填,页面内唯一 | 命名 `b{N}` 递增(现有最大 N+1);重复 id 会被拒绝写入 |
| `type` | string | 必填,白名单(见下) | 未知 type 渲染为错误占位卡,不会崩溃 |
| `x` | number | 0..cols-w | 左起第几列 |
| `y` | number | ≥0 | 上起第几行(松手自动压缩,不必精确) |
| `w` | number | 1..12 | 宽度(列数) |
| `h` | number | 1..20 | 高度(行数,rowHeight=72px) |
| `props` | object | 按 type 定义的键 | 卡片参数,未知键忽略 |
| `hidden` | boolean | 可选 | 页面「卡片管理」开关写入的隐藏标记(隐藏保留几何);AI 修改时保留该字段原样,清理与否不影响渲染 |
| `autoH` | boolean | 可选,默认缺省=固定 | 高度自适应:卡高随内容拉伸(按整行取整,边缘仍落网格线),卡内滚动与文本截断解除;`minH` 行数为下限,长到 20 行封顶后恢复卡内滚动。编辑模式手动拖角拉高会自动退回固定 |
| `minH` | number | 1..20,可选 | 自适应卡的最低高度(行数),默认 3;仅 autoH 卡生效 |

注:文件模式(无本地服务)下忽略 x/y/h,按 blocks 顺序 + w 流式排版——报告转发场景仍美观;文件模式卡片本就随内容拉伸,`autoH` 在其中无视觉效果,`minH` 作为最低高度兜底仍生效。

### 自定义卡(内容自含在 props,不碰 child.json)

| type | 名称 | props | 建议宽度 |
|---|---|---|---|
| `page` | **页面卡(2026-10-24 拍板,自定义卡主型)** | `title`(string), `blocks`(积木数组,见下方「页面卡积木词汇表」), `tone`(可选:green/gold/violet/teal/tea/blue/none;缺省=墨蓝,`none`=白头退出) | w 4-6 |
| `tracker` | 记录卡(分组台账,2026-10-22) | 见下方「tracker 记录卡」节(`title`/`head`/`items`) | w 6 或整行 |
| `text` | [退役 2026-10-24] 文本卡 | 存量渲染兼容,不再新生产;遇到即对话建议换成 page 卡 | — |
| `list` | [退役 2026-10-24] 清单卡 | 存量渲染兼容,不再新生产;勾选需求用 page 卡 `check` 积木 | — |

**页面卡原则(2026-10-24,用户拍板「卡=小页面,不限制,大模型按用户需求自由发挥」)**:每张卡是一个小页面——框架锁定样式与积木词汇表,你( AI)按用户需求自由编排内容。积木词汇表:

| kind | 形态 | props | 用途 |
|---|---|---|---|
| `section` | 小节标题(11.5px 字距眉) | `text` | 页内分区 |
| `p` | 段落(14px 主档) | `text` | 成段说明 |
| `rows` | 要点行组(虚线分隔+Georgia 自动序号) | `items`(字符串数组或 `[{text}]`) | 一行一事的口径/做法;对话可引用「第 N 条」 |
| `kv` | 键值行 | `label`, `text` | 字段对(剂量/频次/地点) |
| `check` | 勾选组(可交互,同退役 list 卡) | `items`(`[{text, done?}]`) | 可执行清单 |
| `callout` | 提示条(`tone: hint` 棕/`warn` 红) | `tone`, `text` | 就医线/特别提醒 |

未知 kind 一律按段落渲染(fail-soft,AI 自由发挥不崩卡);结构校验 server POST 白名单硬拦(kind/条数/必填,tests 21-27)。

**页面卡内容守则**:①**做法优先**——默认写给用户「怎么做」;「为什么」按需(用户问或明确要时再给,一小段即可);②一行一事,要点行 ≤20 字为宜,复合句拆行;③数量克制:blocks ≤30 块、单组 ≤30 条;④源数据半角标点,显示层 cnpunct 统一转全角(渲染器已接,8b 口径 finally 全卡型齐);⑤平实具体写给家人看,不写论文腔;⑥**卡头选色纪律(2026-10-24 拍板:颜色第一职能=定位锚,「想到问题卡→红色直接找到」)**——`tone` 按内容选族色,但避开 `red`/`green` 两个强语义色(红=有问题需行动、绿=正常达标,留给内置语义;就医警示内容用 `callout warn` 表达,不抢卡头红),避免与相邻卡同色(撞色=定位混淆);**色一经选定即稳定**(定位靠记忆,频繁换色毁锚点);用户说「这张卡不要颜色」→ `tone:'none'`。

**自定义卡的创建/编辑/删除唯一路径 = 对话**:页面不提供自定义卡的创建入口(页面只管显隐开关与布局)——家长说「帮我加一张 XX 卡」「把 XX 卡内容改成…」「删掉那张 XX 卡」时,由你( AI)读本规范改 page.json 完成。家长在页面看到空自定义卡时,引导也指向对话。

### 需求分流(家长要一张卡时,先分流再建卡;2026-10-22 验收集走查 docs/custom-card-acceptance-2026-10-22.md 后新增)

| 家长的诉求形态 | 去处 |
|---|---|
| 记事/便条/口径/方法论(写给家人或自己看) | `page` 页面卡(要点行/段落按需组装);事件性流水→`note` 速记 |
| 可勾选的清单(带了没有/做了没有) | `page` 页面卡 `check` 积木 |
| 分组台账(带状态:在读/读完、进行/停用、攒星星/已兑换) | `tracker` 记录卡 |
| 孩子档案类数据(身高/里程碑/问题/回访/计划进度) | 功能卡(profile/growth/milestone/issue/focus/strategy);没有对应功能卡时如实说明,不用自定义卡伪造数据展示 |
| 启动/追踪建设型计划(习惯养成/启蒙路线/入园准备) | 对话里 `add-strategy` 落档(非自定义卡),页面用 `strategy` 在跑计划卡看进度;时间节点部分(如入园报名)再走提醒认领 |
| 时间节点(疫苗/体检/什么时候该做什么) | 前瞻卡+提醒认领:对话里说「记一下 X 月 X 日该 XX」即入前瞻「留意」区,机械节点自动铺开——**不要建自定义卡重复官方能力** |
| 每日数值+趋势(喝奶量/屏幕时间曲线) | 如实说明:页面图表只对官方数据区(生长曲线)开放;提议先记入速记;家长明确要趋势时如实记为待补能力,不硬凑 |
| 需要算术的台账(记账算结余/加权统计) | 如实说明:计数是机械的(数条目),算术不做;提议页面卡手工维护结余行(kv 积木),或降级为纯台账 |

分流原则:接得住就接;接不住就**说明 + 给最接近的替代路径**,不硬凑、不假装。

### tracker 记录卡(2026-10-22 M1)

家长说「我要个绘本管理/用药记录/奖励表」这类带状态的台账 → `tracker`。构件两个,词汇即手册:

```jsonc
{ "id": "b2", "type": "tracker", "w": 6, "h": 5, "autoH": true,
  "props": {
    "title": "绘本管理",
    "head": [
      { "count": "items", "label": "共" },
      { "count": "group", "eq": "在读", "label": "在读", "tone": "watch" }
    ],
    "items": [
      { "text": "波西和皮普:圣诞老人",
        "group": "在读",
        "badge": "在读",
        "tone": "watch",
        "meta": "10-12 起" }
    ] } }
```

- `title` 必填,2-6 字短名词;`items` 必填 1..100 条,每条 `text` 必填(≤20 字为宜)
- `group`(可选)分组名=家长口径的原词,渲染按首现顺序;`badge`(可选)行首描边徽章,通常与 group 同词;`tone`(可选)`ok`(完成/良好)|`watch`(进行/观察)|`todo`(问题/逾期)|`sub`(中性);`meta`(可选)行右短注(日期/备注)
- **计数是机械的**:`head` 只声明口径(`count`: `items` 全部条目数 | `group` 指定分组数,须带 `eq`;≤4 项),数字渲染器从 items 现算——你不写数字,加条目数值自动对
- **状态变更**:家长说「读完了 XX」→ 改该条 `group`/`badge`/`tone`(补 `meta` 日期),整文件替换
- 分组/状态词用家长的原话口径,不发明分类法;单卡建议 ≤30 条,超了建议归档(完结的移出或拆卡)
- 建卡前确认分组结构(「分在读/读完两组行吗?」);机械校验在 server POST,结构坏=拒绝写入并向家长说明

**问题详情覆盖层**(2026-10 起):点击 `issue` 卡问题行(含已解决历史分组行)打开全屏层(当前状态卡→口径卡→时间轴),无路由、文件模式可用;内容只读,变更一律回对话(与自定义卡同边界)。已解决问题头部第 N 天截止结案日,时间轴末位有绿色「结案」大节点。覆盖层内可生成**问题级分享长图**(从 brief 渲染:情况→为什么→全家怎么做→就医线;D 版 2026-10-23=奶油纸传阅品底+茶棕印章+红截至日期,见「分享产物」节),对应 templates.md 问题分享卡节。

## 视觉与内容风格(生长图纸设计系统)

页面视觉=「生长图纸」:儿保手册坐标纸的冷静专业感。**自定义卡的样式由页面框架锁定(你只能改文本),风格自动继承——你管住文本风格就够**:

- **标题**(`title`):2-6 字短名词,如「奶奶须知」「辅食黑名单」「出门清单」。不带 emoji、不带标点、不写句子。
- **页面卡要点行**(`rows.items`):一行一事的短句(不用 `#`、`*`、`-` 等 markdown 符号,积木即结构);口吻写给家人看,平实具体:「吃饭时不看动画片,全家口径一致」好过「关于进餐屏幕时间的原则说明」。
- **页面卡勾选行**(`check.items[].text`):动词或名词开头的 ≤15 字短语,可勾选执行:「水杯」「睡前收好磁力片」;不写长句和解释。
- 数量克制:blocks ≤30 块、单组 ≤30 条,超了拆两张卡或精简。

## 修改规则(给 AI)

1. 只增删改 `blocks` 数组与 `props`,不发明新 type、不改 `version` 与 `layout`
2. **id 唯一**:新卡 id 不得与现有重复(既有页面常用语义 id 如 `profile`,沿用即可;新卡建议 `b{N}` 递增,N 取页面最大编号+1);删除卡片后其余 id 不改
3. 每次修改输出完整 page.json(整文件替换,不做局部 patch)
4. 新卡片给合理的 x/y/w/h(可参考同页面既有卡片的取值;y 不必精确,渲染器会自动压缩)
5. 卡片建议总数 4-8 张;同屏不超过 12 张
6. 修改前向用户确认意图;页面配置损坏的恢复路径=对话里说「帮我重建页面」,由 AI 按本规范整文件替换(「重置默认」按钮 2026-10-10 移除——它恢复的实际是 bundle 内嵌 demo 演示页,对真实用户是误触陷阱)
7. 家长说「加张卡片写 XX」→ 先过上方「需求分流」,自定义卡默认 `page`(按需组装积木),分组台账用 tracker;说「我想在页面看到 XX(档案类数据)」→ 功能卡,没有对应功能卡时如实说明,不用自定义卡伪造数据展示
8. 家长说「这张卡别滚动/让它跟着内容长」→ 该 block 写 `autoH: true`(可带 `minH`);**只给内容长度由文字量决定的卡**(自定义 text/list/tracker、`note`、`issue`、`strategy`),图表类 `growth` 与清单类 `milestone` 的高度由数据结构决定,写 auto 无收益还破坏画布,不要用。auto ≠ 无限:`note` 卡仍受 `limit` 管条数,长到 20 行封顶后恢复卡内滚动

## 渲染器契约

- 两种模式:本地服务(`python3 server.py --open`)= GridStack 编辑器(拖拽/拉角/编辑即保存);文件模式(双击 `web/dist/render.html`)= CSS grid 流式只读

### 窄屏与移动端(2026-10-21 起)

- **断点 ≤720px,基准宽 375px**:板面切**文件模式渲染**(单列流式,`x/y/w/h` 失效,按 blocks 顺序)——移动端与桌面共用同一套卡片组件与排版模型,不引入第二套移动端样式;服务模式窄屏同样走该渲染(只读浏览)
- **布局编辑=桌面专属**:窄屏「编辑布局」禁用(进入窄屏时自动退出编辑态);拖拽/拉角/高度切换/卡片管理均为桌面交互,窄屏保留看板/开病历/分享/导出全部能力
- 卡片内部窄屏规则:行式布局 flex 自然折行、禁止最小宽度撑破;图表 SVG 一律 viewBox+`width:100%`(悬停类增强=桌面可选,触屏由直标/图例兜底);卡头与内边距收敛(20px→14px 档);字阶沿用 9 档白名单不加新档,正文窄屏保持 14px;触控目标命中区 ≥44px(分享钮/展开钮/计数开关,视觉尺寸可不变)
- 弹层窄屏降级:全屏层(问题详情)窄屏即全屏;双栏层(分享弹窗 ≤760px/详情内栏 ≤860px)收为单列
- **分享产物=移动端版式**(手机是分享的唯一终点):**页级导出与卡级分享同一交互**(2026-10-22 拍板:先弹窗预览再导出,版本在弹窗中切换)——工具栏「导出」开导出弹窗(手机版·单列=375px 文件模式板面实时渲染/桌面版·原样=板面 DOM 克隆**缩放适配预览宽,无横向滚动**;导出走隐藏全尺寸节点,成图不受预览缩放影响;单导出钮导当前版本;PDF/单文件网页入口同弹窗);页级长图两版(手机版与窄屏渲染同构,真实卡片组件非家人版重排;桌面版 12 列存档)共用内容规则:生成时**强制展开默认折叠区**(里程碑全达标列表/生长详细记录/问题已解决分组/档案画像变迁,「页面卡片内容都包含」拍板)+「截至日期」角标(时点快照必带,判例 docs/sharing-research-2026-10-01.md §3;卡级与标题行对齐,页级在图内右上角)。**卡级分享(卡片 ⤴)=页面原卡双宽**(2026-10-22 拍板:手机版也显示页面原卡内容,家人卡重排在卡级退役):弹窗版本切换预览(手机版=原卡克隆钉 347px=真机卡宽,cap-mobile 显式套窄屏内边距——媒体查询看视口不看克隆;桌面版=原卡克隆钉页面宽)+**单导出钮**导当前预览,定位靠卡元素 `data-bid`,预览即所发=导出节点就是预览节点;家人卡重排(大字号/条目勾选/匿名/隐私白名单)**仅存问题级**(详情层,问题没有「页面卡」,口径卡是家人版最终形态)。**导出=保存图片,不唤起系统分享面板**(2026-10-22 用户拍板,页级/卡级全链;转发由用户从保存的文件自行发起)。**D 分享层彩色(2026-10-23 拍板「D 先行试点+B 主线」,demo ui-color-2026-10-23)**:分享产物=奶油纸传阅品底(cream 族 token)——问题级家人卡=cream 底+暖棕格线+「带给家人」eyebrow+茶棕印章(孩子名首字,隐名→「宝」)+「截至」日期 todo 红;卡级导出衬底 #fdfdfb→cream(白卡浮奶油纸,cream 只现于圆角外沿与角标间隙);**工作台卡片一律不动**(颜色只出现在离开手机的内容上);按收件人配色因分享数据无收件人字段暂缓;B 主线身份色(黛紫 #6b5a8e=前瞻/在跑计划、黛青 #2e6e6a=成长速记,余复用语义族)已入册 design-system.json identity 节+check-tokens 门禁,卡面应用待 D 试点反馈
- 页面编辑入口唯一=「编辑布局」(2026-10-10 起与卡片管理合并):进入编辑模式后拖拽/拉伸布局+每张卡卡头右侧「固定/自适应」钮切换高度模式(2026-10-21;拖角拉高 auto 卡=自动退回固定)+**底部卡片面板**(瓦片墙:显隐开关,关=写 `hidden:true` 并保留几何;内置卡可 ✕ 删除=block 移出 page.json,随时从「添加卡片」区回来;未上页的功能卡点击上页;自定义卡对话引导);文件模式=纯只读;**内容生产(自定义卡创建/编辑/删除)唯一路径是对话+本规范**
- 未知 type / 坏 props → 错误占位卡(fail-soft),整页照常渲染
- JSON 解析失败 → 保持上一版配置并提示,不白屏
- id 重复 → 拒绝写入(本地服务端 POST 校验)
- 服务端 POST 校验:缺 blocks 数组拒绝写入;id 唯一/非空;autoH/minH 类型;tracker props 结构白名单(title/items/head,见 tracker 节);原子写(tmp+rename)防半截文件

## 新增内置卡的上线清单(贡献者)

1. 组件 + REGISTRY/CARD_META 登记 + 本表加行 + check-card-style 门禁(既有流程);
1b. **身份色决策**:新内置卡必须在 GridBoard `TONE` 表登记 tone 类(身份色映射见规则 2;色相复用语义族优先,真新色相须过 design-system identity 入册+check-tokens 双场景配对),否则渲染为无色头=会被读作自定义卡——内置功能卡不允许无色头;新**自定义卡**类型(对话生产、样式框架锁死)则相反:不挂 TONE,保持白底墨蓝「自建卡」信号(2026-10-23 判例);
2. demo 内嵌页(`web/render.html` 的 embedded page)加上新卡,file mode 开箱可见;
3. **活跃用户的 `data/page.json` 不会自动获得新卡**——功能卡上页只有两条路:用户在「卡片管理」面板手动打开,或对话里 AI 按本规范补 blocks。发布后主动检查活跃档案,需要时按「修改规则」整文件替换补卡(2026-10-09 实例:issue 卡上线后用户页面看不到,根因=只改了 demo 没改用户 page.json)。
