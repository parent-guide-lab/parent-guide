# blocks-spec(页面积木规范)

> 这份文档写给**用户的大模型**看:用户的 AI 读它来修改 `data/page.json`,为家长定制成长视图。
> 设计原则:AI 只改 JSON,不生成代码;渲染器负责校验与兜底。

## 数据文件位置

- `data/child.json` — 孩子档案(单文件,含档案/追踪/回访/速记;键名任意,页面自动取第一个非 `_meta` 键)
- `data/page.json` — 页面配置(本文件讨论的对象)

## 卡片分两类(核心概念)

| | 功能卡(内置) | 自定义卡 |
|---|---|---|
| 数据来源 | 自动读 `child.json` 对应数据区 | 内容全部在 block 的 `props` 里 |
| 谁来更新 | 对话里的写入动作(update-child.py)自动更新 | 家长/AI 直接改 props 文本 |
| 空态 | 引导文案(引回对话) | 「内容为空」提示 |
| 典型用途 | 档案/里程碑/问题/生长/待回访/提醒/速记 | 奶奶须知/出门清单/辅食黑名单 |

**边界:自定义卡不引用 child.json 字段**——child.json 是脚本契约(update-child.py/hot-context.sh),页面配置不往里写数据;反过来功能卡也不需要 props 塞内容。两类卡在 page.json 的 blocks 数组里平权混排。

## page.json 结构(v2:网格坐标布局)

```json
{
  "version": 2,
  "title": "页面标题",
  "child": "child.json 里的孩子键名(可省略,默认取第一个)",
  "layout": { "cols": 12, "rowHeight": 72, "margin": 12 },
  "blocks": [ ...卡片数组,x/y 决定位置,w/h 决定宽高(网格单位)... ]
}
```

布局模型与 grid-layout-plus 同构(`{x, y, w, h}`,12 列网格)。本地服务模式下家长可拖拽/拉伸直接改这些值;AI 改这些值的效果与之完全等价。

## 卡片通用字段

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | string | 必填,页面内唯一 | 命名 `b{N}` 递增(现有最大 N+1);重复 id 会被拒绝写入 |
| `type` | string | 必填,白名单(见下) | 未知 type 渲染为错误占位卡,不会崩溃 |
| `x` | number | 0..cols-w | 左起第几列 |
| `y` | number | ≥0 | 上起第几行(松手自动压缩,不必精确) |
| `w` | number | 1..12 | 宽度(列数) |
| `h` | number | 1..20 | 高度(行数,rowHeight=72px) |
| `props` | object | 按 type 定义的键 | 卡片参数,未知键忽略 |
| `hidden` | boolean | 可选 | 页面「卡片管理」开关写入的隐藏标记(隐藏保留几何);AI 修改时保留该字段原样,清理与否不影响渲染 |

注:文件模式(无本地服务)下忽略 x/y/h,按 blocks 顺序 + w 流式排版——报告转发场景仍美观。

## 卡片类型白名单

### 功能卡(读 child.json,内容由对话自动更新)

| type | 名称 | props | 建议宽度 |
|---|---|---|---|
| `profile` | 孩子档案(卡头 meta 含兄弟姐妹;画像区带截至日期=已展示字段最晚核实时间,超 6 月未核对逐字段提示;「健康」行=长期健康背景 healthNotes,与过敏分栏;「画像变迁」区=profileHistory 留档最新在上,set-profile 改值自动产生) | 无 | w 3-4 |
| `focus` | 今日与回访(就医待办+≤48h 到期回访[过期未做也算]+「接下来的回访」区=窗口外全量+在跑计数入卡头副行;2026-10-13 合并待回访卡,原「下一节点」汇总由在途区首行取代) | 无 | w 4-6 |
| `issue` | 问题追踪(三色计数+问题行,点击开详情覆盖层;「已解决」计数可点——卡内展开历史分组,行同样开详情层) | `status`(`active\|watching\|resolved\|all`,默认空=在管 active+watching) | w 6-12 |
| `milestone` | 里程碑(CDC 检查表) | `months`(number,默认月龄就近档) | w 4-6 |
| `growth` | 生长曲线(身高体重对照 P3-P97,含趋势滑档检测) | 无(数据 child.growth.records,`add-growth` 落档) | w 6-12 |
| `anticipatory` | 前瞻(「记下的」区=认领的 reminders 置顶+节点表时间线:进行中/接下来/已过——疫苗/儿保/口腔/视力/发育盘点/流感季/入园准备,由出生日期+日历机械推导,与 knowledge/anticipatory.md 同源) | 无 | w 4-6 |
| `note` | 成长速记(最新在最上,详情时间轴同款排版) | `limit`(number,默认 5) | w 3-4 或整行 |

> 2026-10-10 产品级退役:`strategy-effect`(策略数据仍在 child.json,由问题详情层「方案」节点/待回访/当前重点聚合呈现,不再有独立卡)、`timeline`(与速记同源重复)、`sleep-week`(睡眠不单独记,无数据生产者)。**2026-10-13 增:`followup`(与「今日与回访」卡重合,全量回访并入 focus 卡「接下来的回访」区)、`reminder`(与「前瞻」卡合并,认领 reminders 并入「记下的」区;add-reminder 写入链与对话认领流程不变)。**老 page.json 残留 block 由渲染器加载时静默剔除。

### 自定义卡(内容自含在 props,不碰 child.json)

| type | 名称 | props | 建议宽度 |
|---|---|---|---|
| `text` | 文本卡 | `title`(string), `text`(string,自由文本) | w 3-6 |
| `list` | 清单卡(可勾选) | `title`(string), `items`(数组 `[{text, done}]`) | w 3-4 |

**自定义卡的创建/编辑/删除唯一路径 = 对话**:页面不提供自定义卡的创建入口(页面只管显隐开关与布局)——家长说「帮我加一张 XX 卡」「把 XX 卡内容改成…」「删掉那张 XX 卡」时,由你( AI)读本规范改 page.json 完成。家长在页面看到空自定义卡时,引导也指向对话。

**问题详情覆盖层**(2026-10 起):点击 `issue` 卡问题行(含已解决历史分组行)打开全屏层(当前状态卡→口径卡→时间轴),无路由、文件模式可用;内容只读,变更一律回对话(与自定义卡同边界)。已解决问题头部第 N 天截止结案日,时间轴末位有绿色「结案」大节点。覆盖层内可生成**问题级分享长图**(从 brief 渲染:情况→为什么→全家怎么做→就医线),对应 templates.md 问题分享卡节。

## 视觉与内容风格(生长图纸设计系统)

页面视觉=「生长图纸」:儿保手册坐标纸的冷静专业感。**自定义卡的样式由页面框架锁定(你只能改文本),风格自动继承——你管住文本风格就够**:

- **标题**(`title`):2-6 字短名词,如「奶奶须知」「辅食黑名单」「出门清单」。不带 emoji、不带标点、不写句子。
- **文本卡正文**(`text`):一行一事的短句(页面按纯文本逐行渲染,不用 `#`、`*`、`-` 等 markdown 符号);口吻写给家人看,平实具体:「吃饭时不看动画片,全家口径一致」好过「关于进餐屏幕时间的原则说明」。
- **清单卡条目**(`items[].text`):动词或名词开头的 ≤15 字短语,可勾选执行:「水杯」「睡前收好磁力片」;不写长句和解释。
- 数量克制:文本卡 ≤10 行、清单卡 ≤8 条,超了拆两张卡或精简。

**贡献者新增内置卡时同样遵守**(机械断言见 `tests/check-card-style.sh`,publish 门禁会跑):

0. **排版规范(2026-10-21 起,全文 docs/typography-spec-2026-10-21.md)**:字号只准用字阶白名单
   10.5/11.5/12.5/14(正文主档)/15(长图正文)/16(卡头标题)/20/22/24/27/54——门禁越档即红,
   新代码禁造中间档;字重只准 400/500/600/700;颜色走 `--ink/--ink-blue/--sub` 配对
   (title=ink-blue、body=ink、辅助=sub);日期/数字列用 `.num-mono` 等宽;面向家长的成段文案
   渲染时套 `cnpunct()`(util.js,CJK 邻接半角转全角——源数据保持半角不动)。
1. 颜色只用 CSS 变量(`--ink/--ink-blue/--sub/--ok/--watch/--todo/--line/--grid-line`),不自造色值;色彩只表达状态,不装饰。
2. 卡头=**纯白标题带**(`.cband`,下边线,坐标纸从带下开始):`h3` 16px/700/墨蓝;**标题行只放标题**(分享钮在带右由页面框架渲染),徽章/计数类 meta 放带内副行 `.cbsub`;内容超出卡高时 `.cbody` 内部滚动、标题带常驻。无 emoji、无图标、无色块。
3. 数字是第一语言:大数字用 `.num-serif`+`.num-hero`/`.num-mid`(Georgia 衬线),日期 tabular。
4. 行式内容走 `.kv`/虚线分隔(`dashed var(--grid-line)`);状态徽章用描边式 `.st`;日期徽章 `.due-b`。
5. 空态=`.src` 一句文字引导回对话,不做大图/emoji 块。
6. 图表:墨蓝线(`--ink-blue`)+白底描边点+越界 `--todo`;区间带 `rgba(90,130,180,.10)`。
7. 无渐变、无投影装饰、无 hover 动效、圆角 ≤12px(图纸是平的、方的)。
8. 强调元素(行动条/提示条)用「登记行」或「细描边框」语言;
   **禁 border-left 彩条+浅色底的组合**——那是 AI 生成界面的模板样
   (2026-10-10 用户判例「太 AI 了」;对照 demo docs/action-bar-styles-2026-10-09)。

## 修改规则(给 AI)

1. 只增删改 `blocks` 数组与 `props`,不发明新 type、不改 `version` 与 `layout`
2. **id 唯一**:新卡 id 不得与现有重复(既有页面常用语义 id 如 `profile`,沿用即可;新卡建议 `b{N}` 递增,N 取页面最大编号+1);删除卡片后其余 id 不改
3. 每次修改输出完整 page.json(整文件替换,不做局部 patch)
4. 新卡片给合理的 x/y/w/h(可参考同页面既有卡片的取值;y 不必精确,渲染器会自动压缩)
5. 卡片建议总数 4-8 张;同屏不超过 12 张
6. 修改前向用户确认意图;页面配置损坏的恢复路径=对话里说「帮我重建页面」,由 AI 按本规范整文件替换(「重置默认」按钮 2026-10-10 移除——它恢复的实际是 bundle 内嵌 demo 演示页,对真实用户是误触陷阱)
7. 家长说「加张卡片写 XX」→ 自定义卡(text/list);说「我想在页面看到 XX(档案类数据)」→ 功能卡,没有对应功能卡时如实说明,不用自定义卡伪造数据展示

## 渲染器契约

- 两种模式:本地服务(`python3 server.py --open`)= GridStack 编辑器(拖拽/拉角/编辑即保存);文件模式(双击 `web/dist/render.html`)= CSS grid 流式只读
- 页面编辑入口唯一=「编辑布局」(2026-10-10 起与卡片管理合并):进入编辑模式后拖拽/拉伸布局+**底部卡片面板**(瓦片墙:显隐开关,关=写 `hidden:true` 并保留几何;内置卡可 ✕ 删除=block 移出 page.json,随时从「添加卡片」区回来;未上页的功能卡点击上页;自定义卡对话引导);文件模式=纯只读;**内容生产(自定义卡创建/编辑/删除)唯一路径是对话+本规范**
- 未知 type / 坏 props → 错误占位卡(fail-soft),整页照常渲染
- JSON 解析失败 → 保持上一版配置并提示,不白屏
- id 重复 → 拒绝写入(本地服务端 POST 校验)
- 服务端 POST 校验:缺 blocks 数组拒绝写入;原子写(tmp+rename)防半截文件

## 新增内置卡的上线清单(贡献者)

1. 组件 + REGISTRY/CARD_META 登记 + 本表加行 + check-card-style 门禁(既有流程);
2. demo 内嵌页(`web/render.html` 的 embedded page)加上新卡,file mode 开箱可见;
3. **活跃用户的 `data/page.json` 不会自动获得新卡**——功能卡上页只有两条路:用户在「卡片管理」面板手动打开,或对话里 AI 按本规范补 blocks。发布后主动检查活跃档案,需要时按「修改规则」整文件替换补卡(2026-10-09 实例:issue 卡上线后用户页面看不到,根因=只改了 demo 没改用户 page.json)。
